# ica1

В цьому документі наведено розгорнуте пояснення до завдання **Capture the Flag (CTF)**, опубліковане на сайті [**VulnHub**](https://www.vulnhub.com/entry/ica-1,748/) автором **"onurturali"**.
Відповідно до наданої автором інформації, рівень складності цього CTF — **ЛЕГКИЙ**, а мета — отримати **root-доступ** до цільової машини та знайти **файли-прапорців**.

Для проходження цього CTF необхідно мати **базові знання команд Linux** та **навички використання інструментів для тестування на проникнення**.
Завантажити оригінал CTF можна [тут](https://download.vulnhub.com/ica/ica1.zip).

> ⚠️ **Примітка**: Для запуску всіх віртуальних машин було використано [**Oracle VirtualBox**](https://www.virtualbox.org/).
> Для проходження CTF використано [**Kali Linux**](https://www.kali.org/docs/introduction/download-official-kali-linux-images/) як атакуючу машину.
> Використані методики призначені **виключно для освітніх цілей**.<br>
> **Відповідальность за їх застосування проти будь-яких інших цілей буде визначатись відповідно чинному законодавству.**

---

В документі розглянуто віртуальну машину ICA1 з платформи для тестування на проникнення яка призначена для тренувань, перевірки надійності мережі та налаштування привілеїв.
Завдання є середньої складності з всебічним випробуванням для відточування навичок тестування на проникнення, пропонуючи реальні сценарії та вектори атак.

У цьому завданні моделюється наступний сценарій.
Згідно з отриманою інформацією, ICA працює над секретним проектом.
Нам потрібно з'ясувати, що це за проект, отримати інформацію для доступу до системи, встановити бекдор.
Для цього необхідно буде пройти кілька рівнів безпеки.
Розпочнемо ми з аналізу, далі виявимо відкриті порти та доступні сервіси, продовжимо ідентифікувати вразливості і, нарешті, використаємо ці вразливості для отримання root-доступу.
На завершення розглянемо деякі рекомендації для підвищення стійкості та надійності віртуальної машини.

## **Короткий огляд кроків вирішення CTF**
1. Завантажити та запустити цільову машину та інструмент для дослідження.
2. Отримати **IP-адресу цільової машини** за допомогою **netdiscover**.
3. Просканувати **відкриті порти** за допомогою **nmap**.
4. Дослідити **FTP-сервіс** на 21 порті.
5. Скачати та дослідити графічне зображення.
6. Дослідити **HTTP-сервіс** на 80 порті. Провести огляд файлової системи web серверів та виявити приховані файли та папки.
7. Знайти зображення, отримати приховані дані.
8. Проаналізувати приховані дані. Виявити вразливості у цільовій системі.
9. Налаштувати файл зі списком ключових слів.
10. Дослідити облікові записи користувачів. Визначити їх паролі.
11. Виявити конфіденційні файли на цільовому комп'ютері. Проаналізувати виявлені файли на наявність корисної інформації.
12. Дослідити файли інших користувачів системи.
13. Дослідити шляхи для підвищення привілеїв. Отримати **root-доступу** до цільової системи.

### **Крок 2: Отримання IP-адреси цільової машини за допомогою netdiscover**
Після завантаження та запуску цільової віртуальної машини у **VirtualBox** першим кроком визначимо її IP-адресу.
У нашому розпорядженні є кілька інструментів, таких як ```arp-scan```, ```netdiscover``` та ```nmap```.
Серед названих інструментів найпростішою є команда ```netdiscover -i eth0 -r 192.168.2.1/24```, де
параметер **-i** задає мережевий інтерфейс, наприклад, eth0 або wlan0,
а за допомогою ключа **-r** можна вказати діапазон мережі для сканування.
Опції рекомендують використовувати у випадку, якщо команда без параметрів виконується тривалий час.
Отже, виконаємо:

```sh
sudo netdiscover i eth0 -r 192.168.2.0/24
```

📌 **Результат**:
Ми достатньо швидко отримали IP-адресу цільової машини — **192.168.2.5**.<br>
![targetip.png](./ica1/targetip.png)

⚠️ **Примітка**: IP-адреси атакуючої та цільової машин можуть бути іншими залежно від конфігурації вашої мережеі.

### **Крок 3: Сканування відкритих портів та доступних сервісів**
На цьому кроці виявимо доступні в системі сервіси та їх версії.
Використаємо ```nmap``` для сканування отриманої IP-адреси на наявність **відкритих портів** та **запущених сервісів**.
Для цього використовуємо команду з ключами **--top-ports -A -sV -P** для виконання агресивного сканування.
- Саме опція **-A** активує агресивні параметри сканування. Вона виконує комплексне сканування, яке включає:
  - **виявлення ОС**; визначає операційну систему цільового об'єкта;
  - **виявлення версій**; визначає версії служб, що працюють на відкритих портах;
  - **сканування скриптів**; запускає скрипти за замовчуванням для збору додаткової інформації про цільовий об'єкт;
  - **трасування**; відображає шлях, яким пакети досягають цільового об'єкта.<br>
- Аргумент **--top-ports** вказує сканувати лише зазначену кількість найпопулярніших портів з файлу **/usr/share/nmap/nmap-services**.
Це дозволяє пришвидшити сканування, перевіряючи лише найімовірніші відкриті порти замість усіх 65535.
- Опція **-sV** дозволяє визначати версії сервісів на портах.
Виконаємо команду:

```sh
nmap --top-ports 100 -A -sV -P 192.168.2.5
```

📌 **Результат**:
Ми побачили три відкриті порти: 22 для служби SSH, 80 для веб-сервера та 3306 для сервера MySQL.
- **22** порт використовується службою **SSH**;
- **80** порт прослуховується веб-сервером;
- **3306** порт використовується запущеним сервером MySQL.<br>

### **Крок 9: Аналіз захешованих паролів**
Як відомо, хеш MD5 неможливо "декодувати" (розшифрувати) у початковий текст, оскільки це не шифрування, а одностороння математична функція.
Однак, щоб підібрати пароль, на практиці використовують метод брутфорсу (перебору) або словникову атаку, який дає такий самий хеш.
Для цього у **Kali Linux** використовують вбудовані утиліти **Hashcat** та **John the Ripper**.
Обидві утиліти є проінстальовані в **Kali Linux**.
Параметри утиліт можна дізнатися виконавши їх з ключем ```--help```.<br>
![hashcathelp.png](./ica1/hashcathelp.png)<br>
![johnhelp.png](./ica1/johnhelp.png)

Спочатку ми повинні зрозуміти, які об'єкти ми отримали у файлі **passwords.txt**.
Файл містить список захешованих паролей. Ще раз відобразимо його вміст

```sh
c3VSSkFkR3dMcDhkeTNyRg==

WDdNUWtQM1cyOWZld0hkQw==
REpjZVZ5OThXMjhZN3dMZw==
Y3FObkJXQ0J5UzJEdUpTeQ==
```

Утиліта **Hashcat** не має вбудованих засобів для автоматичної ідентифікації типу хешу.
Щоб дізнатися, який режим хешу (```-m```) нам потрібен, можна проаналізуйте хеш за допомогою спеціальних утиліт ідентифікації, довідників або online сервісами.

Спочатку використаємо вбудовану в **Kali Linux** утиліту **hashid**.
Якщо утиліта не встановлена, її завжди можна додати до системи виконавши команду ```sudo apt install hashid```.
За допомогою параметра ```-m``` передамо одну з наших стрічок у каманду **hashid**.

```sh
hashid -m "c3VSSkFkR3dMcDhkeTNyRg=="
```

Утиліта не змогла ідентифікувати цей токен. Дійсно він виглядає нестандартно, містить 24 символи і завершується двома знаками рівності.<br>
![hashidunknown.png](./ica1/hashidunknown.png)

Спробуємо скористатися online сервісами.
Зайдемо на сервіс ```https://hashes.com/en/tools/hash_identifier```, внесемо один з наших токенів та спробуємо його ідентифікувати.<br>
![hashidentify.png](./ica1/hashidentify.png)

📌 **Результат**:
Ми отримали підказку від цього сервіса.
Ймовірно спочатку був побудований хеш код від початкового пароля за допомогою алгоритму MD5.
Далі отриманий токен був оброблений за допомогою кодування **Base64**.<br>
![hashpossible.png](./ica1/hashpossible.png)

Згадаємо стандарти хешування, які використовуються при розробці програмного забезпечення.
Як відомо, хеш MD5 складається з 128 біт, що дорівнює 16 байтам.
Проте для зручності читання та передачі у різних програмних утилітах (зокрема у **Hashcat**), ці 16 байт подають у шістнадцятковій (```Hex```) системі числення, через що токен містить 32 символи.
Тобто, кожен байт записується двома символами у 16-й системі числення (цифри від 0 до 9 та літери від a до f).

Однак, результат хешування за алгоритмом MD5 може також складатися із 22 байтів.
Це відбувається, якщо до результату хешування застосовується кодування **Base64**.
В цьому випадку кожен символ 16-ти байтного токена кодується 6-ма бітами інформації.
Якщо математично розрахувати кількість байт, то отримаємо ```128 : 6 = 21.33```.
Оскільки кількість символів повинна бути цілим числом, то щоб помістити всі біти відбувається заокруглення у більшу сторону.
Так отримуються 22 символи.
У стандартній реалізації  **Base64** (наприклад, згідно зі стандартом ```MIME```) дані заокругляються до найближчого числа, яке кратне до 24 бітів.
Тому, до цих 22-х символів додаються два символи доповнення (padding) ```==```, щоб збільшити довжину рядка до 24 символів.

Отже в базі даних зберігаються захешовані паролі в кодуванні **Base64**.
Щоб скористатися утилітою **Hashcat** або **John the Ripper** нам потрібно спочатку декодувати кожен рядок з **Base64** у вихідний 16-символьний токен, який далі перетворити у HEX формат.
Для цього використаємо утиліту **base64**. За допомогою параметра ```-d``` можна задати як файл, так і окремий токен.
Щоб результат не злився в одну стрічку, використаємо утиліту **fold**. За допомогою параметра ```-w``` вкажемо кількість символів в кожній стрічці.
Щоб зберегти результат виконаємо перенаправлення у файл **passwords_md5.txt**. 

```sh
base64 -d passwords.txt | fold -w 16
base64 -d passwords.txt | fold -w 16 > passwords_md5.txt
cat passwords_md5.txt
```

📌 **Результат**:
Ми отримали 16-ти символьні хеш коди паролів користувачів бази даних.<br>
![hash16md5.png](./ica1/hash16md5.png)

Ще раз відобразимо вміст файлу **passwords_md5.txt**.


```sh

```

Утиліта **hashid** розпізнала хеш код та запропонувала режим роботи команди **hashcat -a 2400**.<br>
![hashid16md5.png](./ica1/hashid16md5.png)

Переведемо отримані 16-ти байтні токени у 16-ву систему числення.
Одним з найпростіших інструментів для цього є утиліта **xxd**.
Використаємо її з ключем ```-p``` (postscript), який дозволяє виводити значення послідовно, без додаткової службової інформації.
За допомогою ключа ```-c:500``` задамо кілкість колонок, тобто довжину стрічки в парі з ключем ```-p```.
Щоб не видаляти коди переходу на нову стрічку в якості джерела даних використаємо **base64**.
Результат збережемо у файл **passwords_hex.txt**.

```sh

cat passwords_hex.txt
```

**Hydra** підтримує понад 50 протоколів, включаючи SSH, FTP, HTTP, HTTPS, SMB.<br>

- параметр **perl -e** вказує на необхідність виконати код на мові **Perl**, який буде наданий в аргументі командної стрічки;
- операція **'exec "/bin/bash";'** є кодом на мові **Perl**, який завантажує нову оболонку **/bin/bash** від імені користувача **root**.
Отже виконаємо команду:

```sh
sudo perl -e 'exec "/bin/bash";' .
```

📌 **Результат**:
Ця команда запустила нову оболонку **bash** з правами **root**.
Ми отримавши доступ до всієї системи та можемо виконувати будь-які дії.
Оскільки задана директива **NOPASSWD**, то **sudo** не вимагає введення пароля користувача **lily**.<br>
